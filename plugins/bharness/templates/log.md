# Journal de bord du projet

Ce fichier garde le détail technique de ce qui s'est passé dans le projet, dans l'ordre. Ariane l'alimente en silence : l'utilisateur n'a pas besoin de le lire, mais il peut le demander à tout moment (« montre-moi le détail »).

Règles d'écriture :
- une entrée par événement, courte (deux à six lignes), la plus récente en bas ;
- titre : `## AAAA-MM-JJ HH:MM · agent · type`, avec le type parmi **Fait**, **Problème**, **Solution**, **Remarque**, **Choix** ;
- précis et factuel : commandes, fichiers, branches, versions, URLs publiques de test, messages d'erreur raccourcis et leur cause ;
- jamais de secret (clé, mot de passe, jeton) ni de donnée personnelle de l'utilisateur ;
- ce fichier est versionné avec le projet.

Les préférences et les pièges à éviter vont dans `memory.md`, les décisions validées dans `decisions.md`.
